## 背景

当前 `GenerationView.consoleOverviewIcon` 固定使用 `sparkles` 与 cyan，`consoleOverviewCopy` 固定显示 `Local Render Console`，并固定声称本地 GGUF 已加载且会调用 native backend。真实运行状态并不总是如此：

- `ImageGenerationBackend.status` 可能来自 `UnavailableInferenceBackend`、`MockLocalInferenceBackend` 或 `StableDiffusionCPPInferenceBackend`。
- `GenerationViewModel` 在初始化时把 `backend.status` 保存为 `backendStatus`；UI 应继续只依赖这个统一协议状态，不识别具体 backend 类型，更不能直接碰 native bridge。
- `GenerationView.selectedModel` 只从 `readyModels` 中解析当前 `selectedModelID`，找不到时回退第一个 ready model，因此非 nil 表示当前有一个 selected ready model，nil 表示没有 selected ready model。
- 现有 `generationGate` 的优先级是 backend offline -> no selected ready model -> positive prompt required -> ready，并仅以 `backendStatus.title == "Debug Mock Inference"` 区分 ready gate 的 mock 标题。

因此 overview 必须基于现有 `backendStatus` 与 `selectedModel` 如实表达 backend/model readiness。Positive prompt 是否为空仍只属于 `generationGate` 和 Run 区，不进入 overview 状态。

## 目标

1. 在 `GenerationView.swift` 内建立一个局部、纯派生的 `ConsoleOverviewState`，只读取现有 `viewModel.backendStatus` 与 `selectedModel` 所需事实，不持有可变状态、不触发副作用。
2. 按固定优先级派生四种 overview 状态：backend offline；backend ready 但无 selected ready model；debug mock ready 且有 model；native backend ready 且有 model。
3. 由同一个 `ConsoleOverviewState` 同源驱动 overview 的 SF Symbol、accent color、可见 title、可见 detail，以及组合 VoiceOver label/value/hint，杜绝视觉与辅助功能文案分叉。
4. 保留 v1.145 的横排优先/窄宽度纵排回退和 accessibility Dynamic Type 直接纵排布局，不改变尺寸、spacing、corner radius、panel 风格或页面结构。
5. 保留 v1.146 的 backend/model status pills 内容、布局与组合 VoiceOver，不借本轮重构 pills。
6. 与现有 `generationGate`、`backendStatus`、`selectedModel` 保持一致。若 mock 仍只能通过 `backendStatus.title` 判断，则集中为一个最小 helper，并让 overview 与 `generationGate` 复用它。
7. 保持生成门禁、生成/取消/保存业务、positive prompt required 行为、mock 仅供 UI 开发的边界和 native 推理边界完全不变。

## 非目标

- 不修改 `ImageGenerationBackend`、`InferenceBackendStatus`、`InferenceBackendFactory` 或任何 backend 的公开/内部 API。
- 不给 backend status 新增 kind、enum、capability、mock flag 或 runtime type inspection。
- 不修改 `GenerationViewModel` 的状态生命周期、backend 保存方式、模型选择、参数、生成、取消、结果保存或 alert 行为。
- 不修改 `generationGate` 的条件顺序、title/message（除 ready 标题改为读取同一 mock helper 的等价结果）、icon/color、primary/secondary action、disabled 条件或 accessibility hint。
- 不把 positive prompt readiness、生成进度、取消、结果状态混入 console overview；overview 只表达 backend/model readiness。
- 不修改 v1.145 overview 布局、不修改 v1.146 status pills、不修改 console metrics、Model/Prompts/Run/Result sections 或共享组件。
- 不修改 SwiftData schema、文件存储、模型下载/import、native bridge/XCFramework、StoreKit、Plan、Root 导航、Mac Catalyst、Xcode project 或 workflow。
- 不把 mock backend 描述为 native inference，不把 mock 图片用于生产推理验收。

## 架构与状态依据

### 真相源

1. Backend readiness 只读 `viewModel.backendStatus.isReady`；backend 的用户可见事实继续来自 `backendStatus.title` 和 `backendStatus.message`。
2. Model readiness 只读现有 `selectedModel`。不得改用 `models.isEmpty`、`readyModels.isEmpty`、原始 `selectedModelID != nil` 或文件名字符串，因为这些都不等价于当前 selected ready model。
3. Mock 判定保留当前唯一已存在的契约：`backendStatus.title == "Debug Mock Inference"`。把它集中为一个命名清楚的局部 helper，例如 `isDebugMockBackend`，overview 和 `generationGate` 必须复用；不要在两个位置重复字符串比较。
4. 由于当前 factory 的 ready backend 只有 mock 与 stable-diffusion.cpp，`isReady && selectedModel != nil && !isDebugMockBackend` 对应 native-ready overview。不要扩展 backend API 来解决本轮 UI 映射。

### `ConsoleOverviewState` 约束

- 放在 `GenerationView.swift` 的私有局部边界内，可为 private struct/enum 加纯 factory 或等价的小型实现。
- 输入应是值语义事实，例如 `InferenceBackendStatus` 与 optional selected model/name；输出至少包含 `systemImage`、语义 accent/color、`title`、`detail`、`accessibilityLabel`、`accessibilityValue`、`accessibilityHint`。
- 派生函数不得读取环境、查询、文件系统、SwiftData context 或 native bridge，不得写 `viewModel`。
- 颜色如需映射到 `SwiftUI.Color`，可以在 state 内返回现有 `SciFiTheme` color，或先返回小型语义 accent 再由 view 映射；不要为此建立跨文件设计系统。
- `consoleOverviewIcon` 与 `consoleOverviewCopy` 读取同一份当前 state。避免各自重新判断 backend/model 条件。
- overview 根容器使用组合辅助功能元素，例如 `.accessibilityElement(children: .ignore)`，再从同一 state 设置 label/value/hint；隐藏装饰 icon 的现有语义可以保留。

## 状态矩阵与优先级

以下顺序同时是判断优先级。实现可微调英文措辞，但必须保持每格事实、下一步与禁止语义；Agent B 应在 diff 中给出最终精确文案并让 probe 锁定。

| 优先级 | 输入状态 | 建议 icon / accent | 可见 title | detail 必须表达 | 组合 VoiceOver 必须表达 | 禁止表达 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `backendStatus.isReady == false`，不论是否存在 selected model | `exclamationmark.triangle` / `SciFiTheme.amber` | `Render Backend Offline` | backend 当前不可用，并纳入真实 `backendStatus.title/message` 中有用的原因或修复方向 | label 标识 Local render console；value 明确 Backend offline 及真实 status；hint 说明 backend 可用前不能生成 | `ready`、`loaded`、可调用 native、mock ready、mint/cyan ready accent |
| 2 | backend ready，`selectedModel == nil`，不论 backend 是 mock/native | `shippingbox` / `SciFiTheme.amber` | `Ready Model Required` | backend 已 ready，但没有 selected ready GGUF model；下一步去 Models 下载/import/select ready model | value 同时说 backend ready 与 no ready model selected；hint 指向 Open Models/准备模型 | GGUF loaded、console fully ready、native/mock 可立即生成 |
| 3 | backend ready，存在 selected model，且 `isDebugMockBackend == true` | 清楚的开发/占位符号，例如 `hammer` 或现有可用 SF Symbol / `SciFiTheme.magenta` | `Debug Mock Ready` | 命名 selected model，并明确只会生成 UI development placeholder，native inference 未在使用 | value 明确 Debug mock、selected ready model 和 placeholder 边界；hint 不得暗示真实推理验收 | `native backend ready`、stable-diffusion.cpp 正在使用、真实本地推理已验收 |
| 4 | backend ready，存在 selected model，且 `isDebugMockBackend == false` | `sparkles` 或 `cpu` / `SciFiTheme.cyan` 或 `SciFiTheme.mint` | `Native Render Ready` | 命名 selected model，并明确 linked stable-diffusion.cpp/native backend ready on device | value 明确 Native backend ready 与 selected ready model；hint 说明 prompts/parameters 仍在别处配置后可生成 | mock/placeholder、无模型、backend offline |

额外规则：

- Offline 永远优先于 model；即使查询中存在 ready model，overview 也必须首先且仅以不可误解的 offline 视觉状态呈现，不能使用 ready color。
- No-model 永远优先于 mock/native ready 分支；backend ready 不等于模型 loaded。
- Mock/native overview ready 不等于 `generationGate` ready：positive prompt 为空时 gate 仍必须显示 `Prompt Required`。Overview 不得声称“Ready to generate now”或等价地绕过 prompt required。
- 模型名称必须来自 `selectedModel.name`；不得只显示 family 后声称某个 GGUF 已 loaded。可使用 `selectedModel` 是 ready model 的既有事实，但不要声称 backend 已预加载模型到内存，因为当前架构只在生成时传入 model URL。
- 可见 detail 与 VoiceOver value 应自然、简短、可换行；不能堆叠互相冲突的固定句和状态句。

## 验收标准

- `ConsoleOverviewState` 是 `GenerationView.swift` 内局部、纯派生、无副作用的唯一 overview 状态源。
- 四态及优先级严格为 offline -> backend ready/no selected ready model -> debug mock ready + model -> native ready + model。

- 无模型的任何状态都不说 GGUF/model loaded；mock 不说 native 或 stable-diffusion.cpp 正在使用；offline 不用 cyan/mint 等 ready accent，不说 ready。
- Overview 只表达 backend/model readiness；positive prompt required 仍由原 `generationGate` 独立处理，`canGenerate` 结果不变。
- Mock 判定若仍依据 title，只存在一个集中 helper，并被 overview 与 `generationGate` 复用；不扩展 backend API。
- v1.145 overview 横排/窄宽度回退/accessibility 布局和 v1.146 status pills 的布局、内容、组合 VoiceOver 均保持不变。
- `ImageGenerationBackend`、`GenerationViewModel`、SwiftData、文件存储、native bridge、生成/取消/保存业务、Xcode project、workflow 均无修改。
- 本地轻量检查、两条固定 Swift parse 与纯状态 mapping probe 有真实成功记录；云端 iPhoneOS build 成功。
- `origin/main` 最新 v1.158 artifact 经 Agent C 下载、manifest 与内容核对后，才可宣布版本通过。

## 风险

- `backendStatus.title` 是当前唯一 mock 区分依据，属于脆弱字符串契约；本轮按人工限制集中 helper 并复用，不扩大 backend API。未来 backend 类型增加时应另行设计显式 capability，而不是让所有非 mock ready backend 自动被长期视为 native。
- `selectedModel` 表示 selected ready metadata/model file state，不证明模型已预加载进 backend 内存；文案必须使用 selected/ready，不使用 loaded。
- State 若只驱动 copy 而 icon background/stroke 或 VoiceOver 保留固定 cyan/native 文案，会产生部分失真；mapping probe 和人工逐态核对必须覆盖全部字段。
- Swift parse 只验证语法，mapping probe 只验证纯映射，云端 build 只验证编译集成；Dynamic Type 回退、真实 VoiceOver 顺序和四种运行配置仍需人工交互验证。
- Debug mock 通常只在特定编译 flag 下可构造，native/offline 也受 build 配置影响；无法人工覆盖全部配置时必须保留明确未跑项。
