## 背景

用户总目标仍包括 Mac、iPad、UI/设计、付费能力和本地视频模型部署。本轮必须先按真实代码和现有 CI 判断哪些事情可交付，不能因为总目标持续存在就制造低价值 diff。

### 四条主线审计结论

#### 1. Mac Catalyst、签名和 native Mac slice

- `LocalDiffusion.xcodeproj/project.pbxproj` 的 Debug/Release target 仍是 `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator"`、`SUPPORTS_MACCATALYST = NO`、`SDKROOT = iphoneos`、`TARGETED_DEVICE_FAMILY = "1,2"`。
- 同一工程的 `DEVELOPMENT_TEAM` 为空，仓库没有 `.entitlements` 文件，也没有 Mac signing profile、sandbox entitlement、notarization 或 desktop distribution pipeline。
- `LocalDiffusion/Frameworks/LocalDiffusionNative.xcframework/Info.plist` 只有 `ios-arm64` 和 `ios-arm64_x86_64-simulator`；没有 `macos` 或 `maccatalyst` slice。现有 native build 脚本也只构建 `iphoneos` 和 `iphonesimulator`。
- 结论：Mac 目前不可实现。需要平台/产品决策、Apple 开发者签名、Mac/Catalyst native slice、工程设置、分发和真实 Mac QA；v1.163 不得修改这些配置来伪装可用。

#### 2. Plan、StoreKit、产品标识和 entitlement

- `RootContentView.swift` 的 Plan 只是静态规划信息：StoreKit products 未配置、paid candidates 为 planning only、没有 purchase/restore/receipt/entitlement 状态。
- 源码没有 StoreKit `Product`/`Transaction` 调用、产品标识常量、`.storekit` 配置文件、entitlement persistence、receipt validation 或 App Store Connect 配置。工程 bundle identifier 仍为示例值 `com.example.LocalDiffusion`，签名 team 为空。
- 结论：付费功能没有足够前置条件。缺少人工确认的产品 ID、权益映射、购买/恢复/receipt 策略、App Store Connect 和签名账号时必须暂停；v1.163 不新增购买 UI、StoreKit 依赖或假的 entitlement。

#### 3. iPad/SwiftUI UI 和可验证缺口

- `RootContentView` 已用 `horizontalSizeClass` 区分 iPad regular `NavigationSplitView` 与 compact `TabView`；Models/Video Models 最近已使用 `ViewThatFits`、可换行文本和至少 44pt 操作区，静态审计没有发现足以支持再做一次 Models 文案改动的确定性高价值重叠问题。
- 按 SwiftUI Pro 参考检查，当前相关代码没有本轮必须处理的 `NavigationView`、`onTapGesture` 或 `UIScreen.main.bounds`；现有 `Binding(get:set:)` 和较大的 view 文件是维护性关注点，但不是本轮可证明的用户阻塞，不得借此扩大重构。
- `Scripts/smoke-test-simulator.sh` 当前默认 `DEVICE_NAME` 是 iPhone，完成 simulator build/install/launch/screenshot 后没有统一的截图文件/尺寸摘要断言。
- `.github/workflows/ci-results.yml` 当前运行 Swift parse、native preflight 和 generic iPhoneOS `xcodebuild`，但完全没有运行 `Scripts/smoke-test-simulator.sh`，因此 `NavigationSplitView` 的 iPad 首屏启动、安装和渲染没有 CI 证据。README/`md/test/test.md` 对 smoke 的描述也不能替代实际 run。
- Agent A 当前环境执行 `xcrun simctl list devices available` 得到 `simctl: unable to find utility`，本地没有可用的完整 Xcode/CoreSimulator；这不是代码失败，不能伪造本机 iPad smoke。

#### 4. 视频部署包和无 backend 状态

- `VideoModelPackageInspector`、`AppFileStore` 和 `Scripts/check-video-model-package.sh` 已形成小 fixture 可验证的 `.ldvideo` manifest、路径、regular file、非空、size、SHA-256 和独立目录部署边界。
- `VideoModel` 在 Models 中独立展示 deployment status 与 `Inference unavailable`，不进入 `GenerationView`、`GenerationViewModel` 或 `ImageGenerationBackend`。没有真实视频 engine、帧/编码/播放器、Gallery 视频模型或视频推理接口。
- 结论：当前 `Inference unavailable` 是诚实且必须保留的安全边界。没有 engine/API/模型规格和真实推理环境时，v1.163 不新增视频生成、下载、mock 输出、播放或把 Deployed 改成可推理。

## 本轮选择的最小目标

**建立可追溯的 iPad Simulator smoke contract，并由 `Local Diffusion CI Results` 在 `main` push 中执行。**

本轮是测试/CI 基础设施和文档轮次，不是新的产品能力轮次。目标是让 Agent C 能从最新未加密 artifact 判断：指定的 iPad simulator 是否成功构建、安装、启动，并产生可检查的首屏 PNG 摘要；不能把 CI build 或截图摘要解释为真实 iPad、VoiceOver、Dynamic Type、Mac、StoreKit 或视频推理验收。

## 目标

1. 增强现有 `Scripts/smoke-test-simulator.sh`：
   - 默认自动选择一个可用 iPad simulator；保留 `DEVICE_ID` 和 `DEVICE_NAME` 覆盖能力，明确记录最终 device name/UUID，不再默认只覆盖 iPhone。
   - 保留现有 simulator build、install、boot、launch 和 screenshot 流程；命令失败必须返回非零并带清晰的环境/构建/安装/启动/截图阶段信息。
   - 对截图做小而确定的结果检查，例如文件存在、PNG 可读取、文件大小非零、像素宽高有效，并输出 device、bundle id、app path、launch 结果和截图摘要。只有实现了可靠的像素采样，才允许声称“非黑屏”；尺寸和文件存在检查不得冒充视觉目检。
   - 保持 `DEVICE_NAME` 指定具体设备时的行为可复现；没有 iPad runtime 时必须明确失败或环境阻塞，不能静默回退到 iPhone。
2. 在 `.github/workflows/ci-results.yml` 中执行一次 iPad smoke：
   - 使用现有 native backend 恢复结果和 full Xcode 环境；不要下载模型、视频包或大测试数据。
   - 将 smoke 日志纳入 `ci-results`，并在 `ci-artifact-manifest.json`、`junit.xml`、`ci-failure-summary.md` 中记录独立的 `ipad-simulator-smoke` 检查及退出码。
   - 截图可写到 runner 临时目录；除非确有必要，不把大截图、DerivedData 或 simulator cache 上传到 artifact。artifact 必须包含可读的 smoke summary/log，足以核对设备、启动和截图检查结果。
   - native asset 缺失时可以连同其他 build 检查明确记录“依赖缺失导致 smoke 未执行/失败”，不得把它伪装为 SwiftUI 代码失败或成功。
3. 更新人类和 Agent 使用的测试/验证说明，使默认 CI smoke 的实际范围、失败分类、本地 CoreSimulator 前置条件和未覆盖的真实设备限制保持一致。

## 非目标

- 不启用 Mac Catalyst，不修改 `SUPPORTED_PLATFORMS`、`SUPPORTS_MACCATALYST`、签名 team、entitlements、Mac native slice、notarization 或分发。
- 不实现 StoreKit、产品 ID、purchase sheet、buy/unlock/restore、receipt validation、subscription 或 entitlement persistence；不修改 Plan 的事实边界。
- 不实现视频 backend、视频生成、视频下载、帧/编码/播放器、Gallery 视频实体或真实视频推理；不改变 `Inference unavailable`。
- 不修改图片生成、SwiftData schema、文件存储、native bridge ABI、XCFramework 二进制、模型导入契约、视频包安全校验或业务 UI 布局。
- 不把 iPad simulator smoke 当作真实 iPad、Stage Manager/Split View、VoiceOver、Dynamic Type、Reduce Motion、硬件键盘、pointer、真实 GGUF 推理或截图人工目检。
- 不引入 `smalldata_test`、`develop`、`codeb/...`、PR 流程或新的第三方依赖。
- 不为满足版本号制造无证据的 Models/Generate/Plan/Video UI diff；如果 CI runner 没有可用 iPad runtime，应保留明确阻塞并暂停，而不是改回 iPhone。

## 架构依据

- UI 仍只在 `LocalDiffusion/Views/**`；本轮只改测试脚本、workflow 和验证文档，不改变 UI 到 `ImageGenerationBackend` 的边界。
- `RootContentView` 是 iPad regular 的唯一顶层 `NavigationSplitView`；smoke 只负责启动和首屏渲染证据，不通过私有 API 或测试专用业务分支改变布局。
- `Scripts/smoke-test-simulator.sh` 是项目既有 smoke 入口；`.github/workflows/ci-results.yml` 是既有 `main` 直推结果包入口。新增报告必须复用现有 `ci-results` manifest/JUnit/failure summary 结构。
- 按 SwiftUI Pro 的 accessibility/design/navigation 规则，稳定尺寸只用于按钮/图标等已有控件，不能通过固定屏幕宽度、隐藏错误或降低字号掩盖 iPad 问题；本轮不因 smoke 基础设施而改 UI。

4. 只上传必要的文本报告。检查 workflow YAML 的 shell quoting、`set +e` 状态收集和 Python manifest/JUnit 生成逻辑，不能出现 smoke 实际失败但 workflow 报成功的路径。

- GitHub macOS runner 的 iOS runtime/device 名称可能变化；自动选择必须只选 iPad，匹配失败应成为明确环境阻塞，不得改变验收对象。
- Simulator smoke 只能证明指定模拟器上的工程启动链路和截图输出；不能替代真实 iPad、Stage Manager、Split View、Dynamic Type、VoiceOver、Reduce Motion、硬件键盘、pointer 或人工截图目检。
- SwiftData 首次启动、native asset 恢复、CoreSimulator 服务或 runner 容量可能导致 smoke 失败。结果包必须保留阶段日志，让 Agent C 区分 runner/依赖失败和应用代码失败。
- 额外 simulator build 可能增加 CI 时间；只运行一个 iPad、使用临时 DerivedData、禁止上传 cache/模型/无关截图，并保持 workflow timeout 可控。
- 当前 native XCFramework 没有 Mac/Catalyst slice；不要把 iPad simulator slice 解释为 Mac slice。

## 禁止项和停止条件

- 禁止 Agent B 修改 Mac Catalyst、签名、entitlement、StoreKit、产品 ID、App Store Connect、视频 backend、模型下载或无关 UI。
- 禁止 UI 直接调用 C/Objective-C++ bridge，禁止把 mock backend 或静态 fixture 当真实视频/图片推理验收。
- 禁止使用 iPhone smoke 冒充 iPad，禁止没有 artifact 时声称 CI 通过，禁止使用旧 run/旧 artifact/本地输出冒充本轮结果。
- 禁止提交 DerivedData、截图缓存、simulator cache、模型或历史 artifact；删除本轮临时产物默认使用 `trash <path>`，只在确认的临时/build 产物清理场景按项目环境清理。
- 若完整 Xcode/CoreSimulator、iPad runtime、GitHub 权限或 native Release asset 缺失，记录已完成的静态审计并暂停；不要为了让 workflow 变绿而回退到 iPhone或跳过 smoke。
- 若实现需要人工设备、签名账号、产品决策、付费服务密钥、真实 Mac slice 或视频 engine，立即停止本轮并把该依赖列为阻塞。
- 若没有可稳定验证的 iPad smoke diff，或连续尝试仍只能制造日志/文档噪音，停止并退回“等待人工设备/CI runner 决策”，不要宣布 v1.163 完成。
