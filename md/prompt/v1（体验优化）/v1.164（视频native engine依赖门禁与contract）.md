## 背景与事实边界
- VideoModel/.ldvideo 目前只有本地部署、包检查和状态展示；推理能力明确为 Inference unavailable。
- 当前公开推理边界是 ImageGenerationBackend，图片 native bridge 返回 PNG；没有视频请求、帧输出或视频容器语义。
- 被忽略的 native XCFramework 用 nm 可见 _generate_video、_sd_ctx_supports_video_generation、LTX/WAN 等符号，但项目没有公开视频 header、app bridge、VideoGenerationBackend、编码器、模型兼容 manifest 或许可证/provenance 证明。
- 符号可见不等于稳定 ABI、参数布局、生命周期、错误语义、模型兼容性或可分发许可。不能猜 ABI，不能把符号名当接入证明。
- 本轮完成后应用仍不得生成视频。

## 目标
1. 在推理层与 ImageGenerationBackend 并列建立独立、最小、可测试的 VideoGenerationRequest 和 VideoGenerationBackend contract。
2. 实现明确的 UnavailableVideoGenerationBackend：状态和错误稳定可读；调用只报告不可用/依赖阻塞并抛出明确错误，不返回 PNG、帧、GIF、空数据、mock 或视频。
3. 建立机器可读的 engine/model/license provenance 与 dependency manifest，表达 engine 来源/版本、源码/header/signature 证据、模型组件/兼容性、license/provenance、gate checks 和阻塞原因；缺失信息必须是 unknown/unavailable/blocked，禁止猜测。
4. 增加 native preflight/report，检查公开视频 header、app bridge、视频 contract/实现、engine 来源和 pinned revision、模型/组件兼容 manifest、license/provenance。可观察符号必须与 ABI 证据分开，缺证据则明确 dependency blocked/unavailable。
5. 让本地检查和 .github/workflows/ci-results.yml 结果包包含 manifest、preflight/report、JUnit 或等价摘要、failure summary 和主构建日志；只做报告收集所需的最小 CI 变化。
6. 保持 VideoModel 部署、Inference unavailable、图片 Generate、图片 backend 和 PNG 链路不变；不增加视频生成 UI。

## 非目标与禁止项

- 不修改或猜测 NativeStableDiffusionBridge.h、Objective-C++ bridge、stable-diffusion.cpp ABI、参数结构、signature、回调、释放规则或线程模型。
- 不下载模型、大型测试数据、大依赖、源码包、XCFramework、历史 artifact；测试只用小型临时 manifest/report fixture。
- 不把 PNG、图片序列、GIF、placeholder、mock 或静态 fixture 当视频结果；不实现假 generateVideo。
- 不改变 ImageGenerationBackend、图片 GenerationViewModel、图片模型过滤、PNG 保存或图片 Inference unavailable；不把视频模型注入图片链路。
- 不改变 Mac Catalyst、StoreKit、Plan 购买、产品 ID、entitlement、签名、分发或 App Store Connect。
- nm 符号只能是 observed symbol，不能是 supported/ready。
- 不创建 PR、不切换默认开发流、不回滚其他改动、不执行 gh auth login。Agent C 使用已经登录的账号下载 artifact；权限不足须如实报告。

## 实现步骤
1. 事实审计：确认 native bridge/header、Xcode target、忽略 XCFramework、check-native-backend.sh 和 CI artifact 结构。把 video 符号记为 observed-only；没有受信源码/header 的 ABI 证据时 gate 必须 blocked。
2. 独立 contract：设计最小 VideoGenerationRequest、backend 状态、异步调用、取消和错误边界；不设计会诱导帧/编码输出的假 API。
3. Unavailable 实现：遵守项目 async/actor/Sendable 约定；检查取消、报告 unavailable stage/status、抛出可定位错误；不启动 native、不写文件、不改 SwiftData。
4. manifest schema：至少包含 schema/version、engine name/source/revision、public header 路径和 checksum 或缺失、signature/ABI 证据或缺失、native asset identity、model family/组件/版本/兼容性、SPDX/license/provenance 来源、observed symbols、checks、最终 blocked/unavailable 和 reasons。
5. preflight/report：检查字段类型和文件存在、revision/license/provenance、public header/bridge/contract 是否真实存在；可执行 nm 仅作观察，报告必须写明 “symbols observed != ABI supported”。缺证据时明确阻塞并按项目约定非零或 dependency-blocked 退出。
6. CI 证据：将 manifest、preflight/report、JUnit 或等价摘要、failure summary 纳入未加密 artifact；保留既有 xcodebuild、图片 native preflight、video package check、iPad smoke。
7. 隔离验证：小型 fixture/probe 覆盖 unavailable 无输出、稳定错误、取消/线程边界、manifest 缺字段/错误 schema、symbol-only 被拒绝；确认图片路径未变、视频模型不进入图片入口。
8. 文档和 diff：只写已实现能力和当前无真实视频推理；不含模型、XCFramework、DerivedData、临时 fixture 或无关平台/购买改动。

## 状态、错误与线程边界
- 状态至少区分 unavailable、dependencyBlocked（或等价状态）和未来可扩展 ready；本轮不允许可生成 ready。
- 错误至少区分 contract unavailable、manifest invalid/missing、public ABI evidence missing、model compatibility evidence missing、license/provenance missing、cancellation；不要复用图片 backend 错误。
- unavailable backend 必须 Sendable；采用 actor 时遵守 actor 隔离。请求/错误跨任务安全，不启动 native，不写 PNG/帧/视频，不修改 SwiftData/Gallery。
- 进度若存在，只报告 gate/unavailable，不报告虚构渲染进度；取消后抛出取消错误，不能伪造完成。
- manifest/preflight 使用受控文件边界和确定性输出；只记录路径、摘要、大小和证据状态，不复制大依赖。

- 无法确定 engine 源码 commit、公开视频 header、精确 ABI/signature、生命周期/线程规则、模型组件兼容性或 license/provenance：保持 blocked/unavailable，禁止猜测、反编译接入或符号绕过。
- manifest、workflow 或 target 关系无法小范围安全修改：停止并报告，不扩大为真实 bridge/engine。
- 图片 backend、视频部署状态或 iPad smoke 受影响：停止并退回修复，不用 UI 文案掩盖。
- 需要模型/大依赖、真实设备签名、付费服务、权限、Mac Catalyst、StoreKit 或产品决策：停止并列为后续依赖。
