# v1.161：本地视频模型部署基础

## 版本依据

- 最近已验收版本是 `v1.160`，当前基线为 `HEAD/origin/main=43de193`，工作树应保持干净。
- 本轮分配版本号 `v1.161`，因为这是 v1.160 之后的新能力轮次，不得复用旧版本号。
- 本提示词只供 Agent B 执行实现。Agent B 必须先阅读 `AGENTS.md`、`update_log.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`、`README.md`、`md/prompt/README.md`、`.github/workflows/` workflow 及本提示词。

## 背景与事实边界

Local Diffusion 当前是原生 iOS SwiftUI + SwiftData 应用。当前模型库实际管理 GGUF 图片模型：`LocalModel` 使用 `ModelFamily` 与 `ModelDownloadStatus`，`HuggingFaceDownloadManager` 负责 URLSession 下载/暂停/恢复，`AppFileStore` 管理 `Models`、`Downloads`、`GeneratedImages`。当前图片推理边界是 `ImageGenerationBackend`；`GenerationViewModel` 只接受 ready 的 `LocalModel`，native backend 通过 stable-diffusion.cpp 的 `ldi_sd_generate_png` 返回 PNG `Data`。当前没有 video/frame/AVAsset/MP4 engine，也没有真实视频 backend。

本轮必须把“本地视频模型部署基础”做成真实可交付的管理闭环，但必须诚实地停在部署与能力识别层：用户可以识别一个视频模型包的类型、导入或下载它、看到本地文件和能力状态；应用不得声称已经生成视频。

## 目标

1. 增加独立于图片模型的数据与状态边界，至少能表达一个本地视频模型记录：名称、来源/版本、模型类型或包类型、受支持能力、文件位置/大小、下载进度和错误信息。
2. 支持最小真实闭环：对明确可识别的视频模型类型或模型包进行识别；支持本地导入，必要时沿用 Hugging Face 来源做受控下载；把文件保存到专用、稳定且不与图片 GGUF 混淆的本地目录；重新打开/刷新后能从磁盘与 SwiftData 状态恢复并显示能力状态。
3. 明确展示 `unavailable`、`queued`、`downloading`、`paused`、`failed`、`ready`、`unsupported` 等真实状态。`ready` 只表示视频模型包已完整存在且格式识别通过，不表示视频推理可用。
4. 在架构上为未来真实 `VideoGenerationBackend` 预留协议边界，但本轮不得实现假 backend、帧合成、视频编码或推理调用。
5. 在 Mac/iPad 体验方向保持当前简洁暗色科幻风格，提供清楚的模型类别和能力状态；不得借 UI 文案掩盖能力缺失。

## 本轮最小真实交付

采用能在当前工程内稳定落地的最小闭环，优先实现以下行为：

- 明确定义视频模型类型/包类型识别规则。识别应基于显式类型、受控扩展名/manifest/包元数据和必要的文件完整性检查；不应把任意 GGUF、PNG、图片模型或未知文件猜成视频模型。
- 本地导入至少要有真实的文件复制、非空校验、专用路径边界和重复命名处理；下载路径必须使用真实 URLSession 下载和落盘，不得以 metadata 记录代替文件。
- 视频模型存储不得复用图片 `LocalModel` 的 ready 语义，不得把视频文件放进图片模型/图片输出目录；优先在 `AppFileStore` 增加专用 video models/package 目录和对应安全文件 API。
- 能力状态必须由真实的“类型识别 + 文件存在/非空 + 必要包文件完整性 + 当前 backend 是否存在”推导。没有视频 backend 时，即使模型文件已完整，也应显示类似 `ready / inference unavailable` 的可区分状态，或使用项目内定义的明确 `ready` 与 `unavailable` 组合；不得把它当作图片 backend 可用。
- UI 至少提供视频模型列表/详情、导入或下载入口、文件状态、模型类型、能力状态和错误反馈。入口可以放在 Models 内的独立分区/筛选或独立子视图，但不得让视频模型出现在 Generate 的图片模型选择器中。

## 非目标

- 不实现真实视频生成、视频/帧推理、AVAsset、MP4/MOV 编码、播放器、预览时间线、导出或图库视频实体。
- 不实现 `VideoGenerationBackend` 的生产实现，不调用 C/Objective-C++ bridge，不改 `NativeStableDiffusionBridge.h`、`StableDiffusionCppBridge.mm` 或 stable-diffusion.cpp 接口来假装支持视频。
- 不把图片序列、GIF、占位 PNG、动画 UI、进度条或文案当成视频生成结果；不增加 mock 视频输出作为验收。
- 不改变 `ImageGenerationBackend` 的图片契约，不把视频模型转成 `ImageGenerationRequest`，不让视频记录满足 `LocalModel.isReady`，不让其进入 `GenerationViewModel` 或 Generate 的 ready model 列表。
- 不虚构 Mac Catalyst 支持、StoreKit、付费解锁、entitlement、购买/恢复流程或已经接入的具体视频模型。不得在没有实际适配和验证时声称某模型“可生成视频”。
- 不下载大模型、大测试数据或大 CI artifact；测试只使用小型临时文件、文本 manifest 或内存/`/private/tmp` fixture。
- 不扩展为本轮无关的 Gallery、Prompt、图片生成参数、全局主题或历史文档重写。

## 架构依据与边界

- UI 层只能负责展示、输入、导航和用户反馈。视频模型的识别、路径校验、导入/下载状态和能力推导放在服务/状态层，不能把文件系统或 URLSession 逻辑塞进 SwiftUI View。
- SwiftData 数据层新增独立模型/枚举时，禁止复用或重命名 `LocalModel` 的图片字段来承载视频语义。旧 `LocalModel` 记录必须保持可读取，新增字段必须有安全默认值或采用新增 `@Model`/独立实体降低迁移风险。
- `AppFileStore` 负责视频模型根目录、专用 filename/package 边界、导入落盘、临时下载和存在性/大小检查；不要通过字符串拼接允许路径逃逸，不要覆盖已有文件，不要把临时下载文件误标为 ready。
- `HuggingFaceDownloadManager` 现有逻辑服务于图片模型。只有在能保持模型 ID、目标路径、resume data、状态回写和删除边界清晰时才抽取小型共享下载能力；否则为视频模型增加独立、最小的下载协调器。不得让同一个任务同时改变图片和视频记录。
- 状态层负责异步任务和状态转换，明确区分识别失败、来源不支持、下载中断、文件缺失、文件完整但 backend 不可用。状态变化必须可持久化，刷新/重启 reconciliation 不得把缺失文件留在 ready。
- 推理层继续保持图片 `ImageGenerationBackend` 不变。可以新增只描述能力的 `VideoModelCapability`/`VideoInferenceBackend` 协议边界或 capability provider，但协议不能返回伪造视频，也不能在本轮接入实现。未来真实 backend 应能独立消费视频模型记录和其 package URL。
- UI 应给图片 Generate 一个清晰的过滤边界：只查询图片 `LocalModel` 且仍满足现有图片 ready/file checks；视频列表独立查询，不向 `GenerationViewModel` 注入视频模型。

## 关键文件

先核对并按实际改动范围选择文件，禁止无关修改：

- `LocalDiffusion/Models/AppModels.swift`：独立的视频模型类型、包类型、能力状态和 SwiftData 持久化模型；保持旧图片模型兼容。
- `LocalDiffusion/Services/AppFileStore.swift`：视频模型专用目录、导入/临时下载/最终落盘、路径安全、文件完整性和删除边界。
- `LocalDiffusion/Services/HuggingFaceDownloadManager.swift`：仅在共享下载抽象确实安全时调整；否则新增最小视频下载服务并保持图片下载行为不变。
- `LocalDiffusion/Inference/ImageGenerationBackend.swift`：通常不改图片协议；如新增未来视频能力协议，必须与图片协议并列且无生产实现。
- `LocalDiffusion/ViewModels/GenerationViewModel.swift`：只做必要的图片模型过滤/隔离核对，禁止接收视频模型。
- `LocalDiffusion/Views/Models/ModelLibraryView.swift`：视频模型管理入口、状态/能力展示、导入/下载反馈；保持 iPad/regular width 与动态字体布局可用。
- `LocalDiffusion/Views/Generation/GenerationView.swift`：仅在需要证明隔离时做最小过滤或状态文案调整，不能增加视频生成控件。
- 若工程需要新增独立的 `VideoModel...` service/view 文件，应加入 Xcode project target 并在 prompt/文档中记录；不得因为方便把逻辑放进 View。

## 分步实现

1. **建立事实模型**：先确认当前 SwiftData container、模型注册和 `LocalModel` 查询方式。定义视频模型领域枚举与状态，字段尽量小且可演进；为未知旧 raw value 提供安全 fallback。定义“已部署文件”和“推理 backend 可用”两个独立概念，避免 `ready` 语义含糊。
2. **建立文件边界**：在 `AppFileStore` 增加视频模型目录与受控 API。导入/下载完成前写入临时位置，校验类型、manifest/必需文件、非空和路径范围后原子移动或安全替换到最终位置；已有目标不得盲目覆盖。小型测试 fixture 必须能验证未知类型、缺文件、空文件、路径逃逸和重复名称。
3. **实现识别与能力推导**：新增纯 Swift、可测试的识别器/状态推导逻辑。至少覆盖一个明确支持识别的视频模型包类型和 `unsupported`/`unavailable`；未知扩展名或缺 manifest 必须拒绝或标为 unsupported。不要依据文件名单独宣布 ready。
4. **接入下载/导入状态**：沿用现有 Hugging Face URL 构造约定或安全抽取共享下载器，支持 queued/downloading/paused/failed/ready 所需的最小转移；下载完成后再识别并持久化。恢复数据、取消、删除和刷新不得污染图片模型记录。
5. **接入 UI**：在 Models 中增加独立视频模型区域或分区，显示类型、来源、文件大小、部署状态和能力状态，导入/下载按钮明确可用条件与错误。按钮和可访问性语义必须反映“部署”而不是“生成”。视频 ready 记录不得出现在 Generate 的图片选择器中。
6. **保留未来协议**：如定义 `VideoInferenceBackend`，只放最小能力/状态接口和明确 unavailable 实现；不得添加 `generateVideo` 的伪实现，不得返回 PNG/帧数组冒充视频。未来真正接入时应能替换该边界而不修改图片 backend。
7. **迁移与恢复检查**：检查空数据库、已有 v1.160 数据、包含未知 raw value 的旧/模拟记录、缺少本地文件的记录、下载中断记录。新增视频 schema 不得破坏旧图片模型和现有 Gallery/Generate。
8. **同步文档与验证**：只更新实际受影响的文档，记录当前仍无真实视频推理 backend，执行下述轻量检查，再检查 diff 只含本轮相关文件。

## 风险

- SwiftData 新 schema 可能触发迁移或旧 raw value 兼容问题，必须用默认值/独立实体并由 CI build 验证。
- 供应商视频模型包格式可能不统一；识别范围必须收敛到可证明的 manifest/文件契约，不能凭名称推断能力。
- URLSession 下载、resume data、临时文件与最终文件之间若边界不清，可能产生假 ready 或残留大文件；必须先完成文件校验再更新状态。
- iPad/动态字体/文件导入权限可能暴露布局与 security-scoped resource 问题；本地静态检查不能替代 CI，未做 simulator 的范围要如实记录。
- 当前没有 video backend；即使部署闭环通过，视频推理仍是后续版本，任何更强能力声明都属于验收失败。

## 禁止项与停止条件

- 禁止绕过架构边界、直接从 UI 调 native bridge、把视频模型塞进图片 `LocalModel`/图片 backend、用占位输出或文案伪造视频能力。
- 禁止下载大模型、大 artifact，禁止无确认删除或覆盖用户文件，禁止还原用户/其他 Agent 改动，禁止无关重构。
- 禁止虚构构建、测试、commit SHA、push、run id、artifact 或 Agent C 核对结果。
- 若当前工作区出现无法判断归属的冲突、无法安全迁移现有 SwiftData、无法实现真实文件闭环、缺少必要账号/权限，立即停止并报告阻塞；不要用 mock、猜测或扩大范围绕过。
- 若最小闭环只能实现识别与本地导入而不能安全支持下载，应明确缩小为已验证的导入闭环并记录未完成项，不得把未实现下载写成完成。
