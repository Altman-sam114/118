## 背景与已证实源码现状

`LocalDiffusion/Views/Gallery/GalleryView.swift` 的 `ImageDetailView` 已有以下真实数据流：

- `tagText` 是当前图片的逗号分隔标签草稿，初始化自 `image.tags.joined(separator: ", ")`。
- `draftTags` 使用 `tagText.tagsFromCSV()`，会沿用既有 trim、lowercase、去重和最短长度 normalization。
- `savedTags` 读取 `image.tags`。
- `hasUnsavedTagChanges` 已使用 `draftTags != savedTags` 判断 normalization 后是否存在真实未保存变化。
- Save Tags 当前始终可点，点击后无条件执行 `image.tags = tagText.tagsFromCSV()` 和 `try? modelContext.save()`。
- Save Tags 的 VoiceOver value 已暴露 `Unsaved changes` / `No changes`、draft tags 和 saved tags，但按钮启用状态没有与该值一致。
- Gallery tag 筛选读取 `GeneratedImage.tags`，即已保存值，而不是 `tagText` 草稿。
- Folder picker 经 `folderBinding` 立即写入并保存，和 tags 的显式保存语义不同。
- `SciFiSecondaryButtonStyle` 已读取 `isEnabled`，能提供既有 disabled 视觉状态并关闭 disabled pointer hover，无需修改共享样式。

历史不重复依据：

- v1.30 只增加 Organization 的 VoiceOver 状态，并明确禁止改变 Save Tags 启用状态。
- v1.92 只扩展 draft/saved tags 的 VoiceOver 描述，并保持 Save Tags action 与启用行为不变。
- v1.93 只澄清 Folder 选择会立即保存，并保持 tag 草稿/保存行为不变。

因此 v1.154 首次把既有 `hasUnsavedTagChanges` 接到真实按钮行为，不重做既有 accessibility 文案任务。

## 目标

1. Save Tags 的启用状态必须完全由既有 normalization 后的 `hasUnsavedTagChanges` 决定。
2. 初次打开任意图片详情时，tag 草稿与该图片已保存 tags 一致，Save Tags 禁用。
3. 增加、删除、替换、清空或重排会改变 normalized tags 数组的草稿后，Save Tags 启用。
4. 仅空格、大小写、重复项或会被既有 normalization 丢弃的无效 token 发生变化，但 normalized tags 与已保存 tags 相同，则 Save Tags 保持禁用。
5. 点击已启用的 Save Tags 时继续沿用现有 normalization，写入 `image.tags` 并保存 SwiftData；保存动作完成后，草稿同步为实际 normalized 已保存 tags，按钮恢复禁用。
6. 从图片 A 切换到图片 B 时，不得把 A 的草稿或启用状态泄漏到 B；B 必须以自己的已保存 tags 初始化并显示禁用状态。
7. VoiceOver 的 value、hint 和系统 disabled trait 必须与真实按钮状态一致。
8. 保持现有 44pt 命中区、Sci-Fi 样式、Dynamic Type 布局、iPad pointer 行为和原生键盘可聚焦/触发语义。
9. 同步 README、核心流程、流程图和更新日志，使文档反映 tags 显式保存按钮的真实 dirty-state gate。

## 架构依据

- `ImageDetailView` 位于 `LocalDiffusion/Views/Gallery/**` UI 层，现有职责就是维护当前图片的 tag 输入草稿并通过 `ModelContext` 执行显式保存；本轮应留在该边界内。
- `GeneratedImage.tags` setter 与 `tagsFromCSV()` 已提供 normalization。不得把 normalization 复制到 View、修改模型层或另建服务。
- 唯一 dirty-state 真相源应继续是 `hasUnsavedTagChanges = draftTags != savedTags`。按钮、VoiceOver 状态和保存后状态都必须引用同一判断，避免平行布尔状态漂移。
- Folder 和 tags 的保存时机是既有产品边界：Folder 立即保存，tags 显式保存。本轮不得合并两条路径。
- Gallery filter 依赖 SwiftData 已保存 tags；草稿只属于详情 UI，不能进入查询/filter 数据流。
- UI 不接触 `ImageGenerationBackend` 或 C/Objective-C++ bridge。

## 实现步骤

### 1. 用既有 dirty state 控制按钮

在 `ImageDetailView` 的 Save Tags 原生 `Button` 上增加：

```swift
.disabled(!hasUnsavedTagChanges)
```

要求：

- 不新增独立 `@State isSaveTagsEnabled`、`isDirty` 或手工切换布尔值。
- 不通过 opacity、手势 guard 或 action 内 early return 模拟 disabled；必须使用 SwiftUI `.disabled`。
- 保留 `SciFiSecondaryButtonStyle()`、当前 Label 和至少 44pt frame。共享 style 已处理 disabled 视觉与 pointer 状态，不修改它。

### 2. 保存一次解析结果并同步规范化草稿

把 Save Tags action 收敛为单次读取当前 normalized draft，例如：

1. 计算一次 `let normalizedTags = tagText.tagsFromCSV()`。
2. 将该值赋给 `image.tags`，继续使用既有模型 setter normalization。
3. 沿用既有 `try? modelContext.save()` 错误处理边界，不在本轮扩展错误 UI。
4. 将 `tagText` 同步为实际保存后的 `image.tags.joined(separator: ", ")`，使 TextField 可见草稿、VoiceOver draft 描述和持久化 normalized tags 一致。

同步 normalized 草稿是必要行为：例如输入大小写、额外空格、重复 tag 或无效短 token 后，保存结果可能与原始文本不同。保存后若保留原始文本，按钮虽然可能因 normalized 比较而禁用，但可见“草稿”仍与真实保存值不一致。不得通过修改 normalization 规则解决该问题。

保存后必须满足 `draftTags == savedTags`，从而由同一 computed property 自动恢复 disabled；不得手工写 dirty flag。

### 3. 保证 selected item 身份切换正确

核对 `navigationDestination(for: UUID.self)` 到 `ImageDetailView` 的生命周期。采用最小、明确的 SwiftUI 身份或 `image.id` 变化同步方式，保证详情实例从图片 A 更新到图片 B 时：

- `tagText` 重置为 B 的 `image.tags.joined(separator: ", ")`。
- B 初始 `draftTags == savedTags`，Save Tags 禁用。
- A 未保存草稿不会写入 A，也不会显示在 B。
- 不使用通用 `.onAppear` 无条件覆盖当前图片仍在编辑的草稿，避免 sheet 返回、重绘或普通重新出现时丢失同一图片的未保存输入。

可使用由 `image.id` 驱动的 view identity，或仅在 `image.id` 真正变化时同步 `tagText` 的等价局部方案。不得增加跨图片草稿缓存或自动保存。

### 4. 对齐 VoiceOver 与键盘语义

- 保留 `Save image tags` accessibility label。
- 保留 `saveTagsAccessibilityValue` 对 `Unsaved changes` / `No changes`、draft tags 和 saved tags 的组合描述，并确保它继续引用同一 `hasUnsavedTagChanges`。
- 将 accessibility hint 设为状态一致的 computed 文案或等价实现：有变化时说明保存当前 tags；无变化时说明当前草稿与已保存 tags 一致、没有可保存变化。
- 使用 `.disabled` 提供系统 disabled trait；不要伪造朗读中的 Enabled/Disabled 状态，也不要隐藏按钮。
- Save Tags 保持原生 `Button`，启用时可由 Full Keyboard Access 聚焦和触发，禁用时不能通过触摸、pointer 或键盘触发无条件 SwiftData 写入。
- 不新增全局 keyboard shortcut，不把 Return/Submit 绑定为保存，不改变 TextField 编辑和换行语义。

### 5. 保持 Dynamic Type 与 iPad 行为

- 不改变 Tags TextField 当前普通字号 `1...3` 行、accessibility Dynamic Type `3...6` 行策略。
- 不改变 Organization Form section、按钮 Label、44pt 最小高度、对齐、颜色和 Sci-Fi panel 样式。
- 普通字号、accessibility Dynamic Type、iPhone、iPad regular/Split View 下均不得因状态修复产生文字溢出或控件重排回归。
- iPad pointer 在按钮启用时保留既有 hover affordance，禁用时由共享 style 的 `isEnabled` 逻辑停止 hover。

### 6. 严格限制 diff

预期源码修改只在 `LocalDiffusion/Views/Gallery/GalleryView.swift` 的 `ImageDetailView` 局部完成。`AppModels.swift` 和共享按钮 style 只读核对，不应修改。不得借机重构整个 Gallery 文件。

## 风险

- SwiftUI `@State` 若未按 `image.id` 隔离，详情目的地复用时可能把上一张图片的草稿带到下一张；必须显式核对 selected item 生命周期。
- 保存后若不把 `tagText` 回写为 canonical `image.tags`，可见文本可能保留被 normalization 丢弃的内容，造成“按钮禁用但草稿文本看似不同”的不一致。
- 若改用原始字符串或 Set 比较，会分别产生 cosmetic false positive 或丢失既有数组顺序语义；必须保留当前数组比较。
- 当前 `try? modelContext.save()` 不提供失败反馈。本轮沿用既有边界，持久化失败 UX 不在范围内，应记录为残余风险而非扩展实现。
- 云端 build 不能替代真实 VoiceOver、iPad pointer、Full Keyboard Access、Dynamic Type 和图片切换交互目检。
