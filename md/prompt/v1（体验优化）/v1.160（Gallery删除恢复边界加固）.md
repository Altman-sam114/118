## 背景
v1.159 artifact 已通过 Swift parse、native preflight 和 iPhoneOS build，但专项运行时审查发现以下缺陷：

1. 删除进入 `restorePending` 后，原 PNG 正常缺失、staged PNG 仍保留；Gallery `.onAppear` 或 Refresh 执行 `reconcileImageFiles()` 时会误删仍应保留的 metadata，破坏 Retry Restore。
2. `.DeletionStaging` 没有拒绝 symlink，没有验证解析后的真实路径仍在 images root 内，也没有在 move 前证明 original 与 staging 同卷。
3. `moveItem` 抛错后当前只检查 staged 是否存在，没有完整检查 original/staged 四态；original 消失时可能降为普通失败或错误进入 sourceMissing 重试。
4. `ImageDeletionToken` 可被模块内调用方用 id、original URL、staged URL 和 payload 重组，AppFileStore 没有保持唯一构造权。
5. `Retry Delete Metadata` 与 `Retry Restore` 可见按钮缺少当前图片 `accessibilityValue`，与 Retry Cleanup 不一致。

本轮必须最小修复这些边界，并用最终生产 API 的真实 probe 和固定检查验证，不扩大到跨启动清理。

## 目标
- `restorePending` 活动请求的 metadata 不被 Gallery `.onAppear` reconciliation 删除。
- `restorePending` 活动请求的 metadata 不被 Refresh Gallery reconciliation 删除。
- 保护条件绑定 active request 的 image UUID、filename 和 phase，不全局跳过其他缺失文件清理。
- 状态离开 `restorePending` 后恢复普通 reconciliation，不建立永久豁免。
- staging 目录必须是实际目录且不是 symbolic link；symlink 一律拒绝。
- 标准化并解析 images root、original、staging directory 和 staged destination 的 symlink。
- 解析后的 staging 路径必须严格位于解析后的 `imagesURL` 内，拒绝兄弟前缀和路径逃逸。
- stage move 前验证 original 与 staging directory 的 volume identity 相同；缺失或不一致时 fail closed。
- `moveItem` 抛错后检查 `(originalExists, stagedExists)` 四态并返回真实结果。
- original 一旦消失，不得降为普通 stage failure，也不得伪装成 `.sourceMissing`。
- token 只能由 `AppFileStore` 构造；Gallery 不能读取 URL 字段后重组 token。
- restore/finalize 只能接收 AppFileStore 签发的原 token。
- Retry Delete Metadata 与 Retry Restore 增加当前图片 `accessibilityValue`。
- 保持 v1.159 独立 `ModelContext`、cleanupPending 和 success-only dismiss/path/focus 语义。

## 当前架构依据
- `AppFileStore.swift` 是图片路径及 stage/restore/finalize 的唯一文件系统边界。
- v1.159 使用 `GeneratedImages/.DeletionStaging/<UUID>.png` 做隐藏同卷暂存。
- 当前路径验证主要比较未解析 `.path`，不足以抵抗 staging symlink 或真实路径逃逸。
- 当前 token 的 memberwise construction 需要收敛为 opaque capability。
- `GalleryView` 父级持有唯一 request、phase、token 和 error。
- `restorePending` 表示 metadata 仍存在，只允许针对同一 token Retry Restore。
- `.onAppear` 和 Refresh 最终调用同一个 `reconcileImageFiles()`。
- reconciliation 保护必须由父级 active request/phase 派生，AppFileStore 不依赖 SwiftUI 状态。
- Retry UI 使用 request snapshot 的图片上下文，不依赖可能被 `@Query` 移除的对象。

## 必须保持的状态机
```text
restorePending(active request)
  -> onAppear：跳过该 request 的 metadata 缺失文件清理
  -> Refresh：跳过该 request 的 metadata 缺失文件清理
  -> Retry Restore：只恢复同一 token 的 staged PNG
  -> 成功：metadata 保留，original 恢复，可再次 Delete
  -> 失败：仍为 restorePending，不删 metadata，不 finalize
```

move 抛错后的四态：

| original | staged | 必须行为 |
| --- | --- | --- |
| 存在 | 不存在 | stage 未发生；普通明确失败；metadata 不动 |
| 不存在 | 存在 | 已转移；保留原 token；进入 restore-required |
| 存在 | 存在 | 双位置冲突；保留两边；不删 metadata |
| 不存在 | 不存在 | payload lost/unknown；严重不确定失败；禁止普通/sourceMissing 重试 |

- 四态判断必须发生在捕获 production move error 后，不能只写在 probe 镜像中。
- `.sourceMissing` 只表示 move 前已确认 original 不存在。
- 任一 path/symlink/volume 验证失败都必须发生在 metadata delete 前。

## 实现步骤
1. Agent B 按必读顺序读取项目事实和本提示词；同步 `origin/main`，确认 `main`、最新基线和干净工作区。
2. 将 deletion token 改为只能由 `AppFileStore` 构造的 opaque 类型，移除调用方可见的完整 memberwise initializer。
3. token 只暴露 Gallery 状态机必需的只读 identity/disposition；original/staged URL 保持 AppFileStore 私有。
4. restore/finalize 复用原 token，并在每次操作前重验生产路径身份。
5. 若 `.DeletionStaging` 是 symlink、非目录或解析后越出 images root，抛出明确错误，不跟随、不替换、不删除。
6. containment 使用标准化 URL、`resolvingSymlinksInPath()` 和目录组件比较；禁止仅用 `hasPrefix`。
7. move 前读取可靠 volume identity；无法读取或不同卷均拒绝。
8. 如需可测注入点，只增加 internal 最小 seam，不建立通用文件系统抽象。
9. 重写 move catch，实际读取 original/staged 四态，并保留底层 move error。
10. `(false,false)` 不得创建 sourceMissing token；`(true,true)` 不得自动删任一文件。
11. reconciliation 仅在 active request UUID/filename 匹配且 phase 为 `restorePending` 时跳过该 metadata。
12. 同一 guard 同时覆盖 `.onAppear` 和 Refresh 共用路径，其他图片仍正常 reconciliation。
13. 被保护项仍加入 referenced filenames，避免 orphan 枚举产生新的误删。
14. 为 Retry Delete Metadata 和 Retry Restore 按钮增加 request snapshot 图片 `accessibilityValue`。
15. 保持 Retry Cleanup 的 value/hint，三种 retry 的副作用语义必须准确。
16. 不改变独立 metadata context、already absent、cleanup pending 和完整成功限定导航清理。
17. 更新 README、flow、flowchart 和 update_log，只记录真实实现与验证结果。

### 生产 API 真实 probe
- 在 `/private/tmp/localdiffusion-v1.160-file-probe-<unique>/` 使用小型可识别 PNG bytes 和真实 `FileManager`。
- probe 直接编译/调用最终生产 `AppFileStore` stage/restore/finalize API，不复制 token、路径或四态逻辑。
- 正常 stage 证明 bytes 不变、original 消失、staged 存在且真实 volume identity 相同。
- staging symlink 指向 images 内或外都必须拒绝；外部 sentinel 不受影响。
- 普通 staging 目录解析后必须位于 images root，兄弟前缀目录不得通过。
- 注入 move 抛错后覆盖四态；每态输出 case、状态和 PASS/FAIL，任一失败非零退出。
- `(false,false)` 不得返回普通失败/sourceMissing，不得调用 metadata probe callback。
- `(false,true)` 用原 token Retry Restore 并恢复 bytes；probe 不得构造 replacement token。
- `(true,true)` 保留两处文件且 metadata 未调用。
- sourceMissing 只覆盖 move 前 original 已不存在，与 move-error `(false,false)` 区分。
- 无可控第二 volume 时，真实 resource values 验证同卷成功；跨卷拒绝可用最小 identity seam，但必须注明注入。

### 固定 source-contract 检查
- token 没有 Gallery 可调用 initializer，Gallery 不能读取 original/staged URL 重建 token。
- restore/finalize 调用都传递 AppFileStore 原 token。
- move catch 覆盖四态，original 缺失不落入普通失败或 sourceMissing。
- `.onAppear` 与 Refresh 共用 reconciliation 对 active restorePending 跳过 metadata delete。
- Retry Delete Metadata 与 Retry Restore 均有图片上下文 `accessibilityValue`；Retry Cleanup 未回退。
- 固定检查不能替代真实文件 probe、Swift parse 或人工 UI 验收。

## 风险和禁止项
- move 与 SwiftData save 仍非单一原子事务；本轮不提供跨启动 token 持久化或清理。
- volume identity 读取失败必须 fail closed，不能跳过验证。
- 禁止 reconciliation 删除 active restorePending metadata。
- 禁止跟随 staging symlink、只比较未解析字符串路径或跨卷 stage。
- 禁止 original 消失后普通/sourceMissing 重试，禁止覆盖文件或吞 move error。
- 禁止 Gallery/probe 构造、复制或重组 token。
- 禁止主 context 删除目标 metadata、rollback、reinsert 或伪造 metadata。
- 禁止修改跨启动清理、schema、native、workflow、StoreKit 或 Mac Catalyst。
- 禁止新增大架构、依赖、测试 target、PR 或非 main 流程。
- 禁止伪造 probe、parse、build、push、run、artifact、VoiceOver 或 Agent C 结论。
