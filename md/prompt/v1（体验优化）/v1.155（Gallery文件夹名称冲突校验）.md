## 背景

`GalleryView` 的 New Folder 和 Rename Folder 目前共用 `FolderNameEditor`。编辑器只把名称 trim 后判空，Save 在非空时启用；创建直接插入 `GalleryFolder`，重命名直接修改 `folder.name`，因此 `Travel`、`travel` 或其他经本地化大小写不敏感比较不可区分的名称仍可被新增。

`GalleryFolder` 当前仅对 UUID `id` 使用 `@Attribute(.unique)`，`name` 是普通字符串。现有用户数据可能已经包含重复或不可区分的名称。本轮只能阻止后续新建/重命名产生冲突，不能对历史数据加 unique constraint、迁移、自动改名、删除或合并。历史重复文件夹必须继续分别按 UUID 存在、显示、筛选并保留各自图片归属。重命名表单保存自身原名也必须可用，不能因为自身记录或已有历史重复记录而把无变更保存误判成冲突。

## 目标

1. New Folder 与 Rename Folder 共用同一套名称 normalization、冲突比较和 validation state。
2. 候选名与已有名都先用 `.trimmingCharacters(in: .whitespacesAndNewlines)` trim，再使用 `localizedCaseInsensitiveCompare(_:) == .orderedSame` 判断是否不可区分。
3. 新建时，只要任一已有文件夹名称与候选名不可区分，就显示真实可见的 inline 冲突状态并禁止保存。
4. 重命名时，候选名 trim 后若与该文件夹进入编辑器时的原名 trim 后完全相同，必须视为合法自身原名并允许保存，即使历史数据中另有不可区分的重复记录。
5. 重命名为非自身原名时，排除当前文件夹 UUID，再检查其余文件夹；任何不可区分名称都构成冲突。
6. Save 只在名称 trim 后非空且 validation 无冲突时启用；点击 Save 也必须经过同一规则，不能只依赖按钮视觉状态。
7. 在 Folder name 字段附近提供每种状态真实可见、可换行的 inline validation 文案，不能只用 toolbar disabled、颜色、placeholder、alert 或 VoiceOver 表达错误。
8. Folder name 字段、inline validation 和 Save 的 VoiceOver label/value/hint/error 文案必须由同一 validation state 派生，并与系统 disabled trait 一致。
9. 保持 Form 在 iPhone、iPad、键盘输入和 Dynamic Type 下可滚动、可聚焦、无重叠或截断；状态文案允许多行，不使用脆弱固定高度。

## 非目标

- 不给 `GalleryFolder.name` 添加 `@Attribute(.unique)`，不修改 SwiftData schema、container、migration plan 或模型 API。
- 不扫描、迁移、合并、删除、自动改名或重新分配已有重复文件夹数据。
- 不改变文件夹删除、筛选、排序、选中状态、图片 `folderID` 归属或 Folder picker 即时保存行为。
- 不改变图片删除、文件存储、orphan reconciliation、标签保存/筛选、详情、分享、复用或重新生成。
- 不把比较改为简单 `lowercased()`、手写 locale folding、正则、diacritic-insensitive、width-insensitive 或唯一索引语义。
- 不新增跨页面 service、ViewModel 或数据层 abstraction；不修改 Models、Prompts、Generate、Plan、native backend、StoreKit、Mac Catalyst、Xcode project 或 workflow。
- 不把本轮扩大为持久化错误提示改造；现有 `try? modelContext.save()` 风险只记录，不在本轮处理。

## 当前架构依据

- `GalleryView` 位于 UI 层，持有 `@Query` 的 `[GalleryFolder]`、创建/重命名 sheet 状态和现有 SwiftData 保存入口；名称冲突是 Gallery 编辑入口的交互校验，应留在 `LocalDiffusion/Views/Gallery/GalleryView.swift`。
- `FolderEditorState` 保存稳定 UUID 和进入编辑器时的原名，足以区分新建与重命名、排除自身记录，并落实“自身原名允许”的规则。
- `GalleryFolder` 继续以 UUID 作为身份；名称不承担数据身份或关系约束，`GeneratedImage.folderID`、筛选和删除流程因此无需变化。
- validation 必须是输入、当前编辑身份、原名和已有 folders 的纯派生状态。inline 文案、Save `.disabled`、Save action guard 和 accessibility 文案都应消费同一结果，不能维护会漂移的平行 `Bool` 或手工 error state。
- `FolderNameEditor` 已使用原生 `Form`、`TextField`、toolbar Button 和 Sci-Fi screen 样式；在此结构内增加可换行的 inline 状态最能保持键盘、iPad 和 Dynamic Type 的系统行为。

## 比较规则

按以下顺序实现，Agent B 不得自行替换语义：

1. `candidate = name.trimmingCharacters(in: .whitespacesAndNewlines)`。
2. `candidate.isEmpty` 时状态为 required，不执行冲突比较，Save 禁用。
3. 对已有 folder 名也先执行相同 trim；只通过 `candidate.localizedCaseInsensitiveCompare(existingTrimmed) == .orderedSame` 判断不可区分。
4. 新建模式没有自身 UUID；任一已有 folder 命中即为 conflict。
5. 重命名模式先判断 `candidate == originalName.trimmingCharacters(in: .whitespacesAndNewlines)`。精确等于自身 trim 后原名时直接合法，保证历史重复数据中的记录仍可无变化保存。
6. 若不是精确自身原名，则忽略 `folder.id == editingFolderID` 的记录，再对所有其他 folder 执行第 3 步比较；任一命中即为 conflict。
7. 不因候选名与自身原名仅有大小写或其他 localized-case-insensitive 等价差异而自动套用“精确自身原名”豁免；这属于名称变更，仍需对其他 folder 检查。若其他 folder 不冲突则允许。
8. 已有重复记录不触发后台修复。浏览、筛选和图片归属继续按 UUID；只在用户提交新建/重命名草稿时应用上述 gate。

建议定义局部状态枚举或等价值，例如 `required`、`conflict`、`valid`，并由一个 helper 计算。具体命名可遵循现有代码风格，但规则必须唯一且可复用。

## 风险

- `localizedCaseInsensitiveCompare` 会依赖用户当前 locale；这正是本轮指定语义。不要改成 locale 固定、简单 lowercasing 或额外 diacritic/width folding，否则可观察行为会变化。
- 历史重复记录会让一般的“排除自身 UUID后查其他记录”仍把无变化保存判为冲突，因此精确自身 trim 后原名豁免必须先执行。
- 若 inline 文案、Save `.disabled` 和 action guard 各自重算不同条件，输入变化后会出现视觉、VoiceOver 与实际提交不一致；必须集中为一个派生状态。
- `@Query` folders 在 sheet 展示期间理论上可能变化。Save action 必须基于当前可用 folders 再检查同一规则，避免只在表单初始快照校验；不要用 schema unique constraint规避此问题。
- 当前 `try? modelContext.save()` 仍可能静默失败，本轮不扩大到持久化错误 UX，必须在版本记录中保留该风险。
- 云端 build 不能替代真实 VoiceOver、iPad、Full Keyboard Access、Dynamic Type 和带历史重复数据的交互目检；未实际执行时必须明确记录。
